= G7: seed-issue replay proof

Issue: ituob/service-publications-docs#84.
Baseline: main at `7d94b1c1a6425396525dc6e153ee09eece74cd54` (after #66).
The hypothesis is proven. `DirectoryChangeSource#each_sorted` excluded only
issues strictly older than the seed, so a post-amendment annex replayed its own
issue's amendments. ADD/LIR overwrote seed rows; an E.118 SUP/ADD pair removed
and restored a row already replaced in the seed. This was not necessarily a
second active entry: replay stores rows by key. Duplicate-add findings measure
attempted additions of existing keys, not duplicate final hash keys.

== Row and annex evidence

The publication dates in `ob-issues/{issue}/meta.yaml:2` equal the annex
`position_on` in `ob-issues/{issue}/annexes.yaml:2`: 1161 is 2018-12-01,
1109 is 2016-10-01, 1114 is 2016-12-15, and 1162 is 2018-12-15.
The routed Note PQ seed belongs to the same E.164 annex.
Dates support the row evidence; dates alone are not the proof.

* `datasets/1161-E.118/data.yaml` already has the AWCC replacement for
  `89 93 01`, Namibia `89 264 33`, and the repeated Austria/Thailand rows;
  `89 420 06` is absent. Compare its six `changes/1161-*.yaml` patches.
  Address splitting and effective-date formatting differ between extraction
  formats, so the rows are not all byte-identical. Skipping replay preserves
  the annex row in full rather than overwriting its richer representation.
* `datasets/1114-E.164D-Note-PQ/data.yaml` already has `+883 5140` and
  Com4 Sweden AB at `+883 190`. The two ADDs and two LIRs in `changes/1114-*`
  repeat those keys; amendment rows additionally carry `status: assigned`.
* `datasets/1162-E.212/data.yaml` already has all six ADD codes
  (`208 23`, `208 29`, `208 33`, `208 500`, `208 700`, `272 18`) and
  the LIR network SEM@FOR77 at `208 86`. Both withdrawals (`268 02`,
  `268 07`) are absent. Country translations differ in shape, but the network
  names agree with `changes/1162-*`.
* `datasets/1109-Q.708B/data.yaml` already has all three ADD codes
  (`2-249-2`, `4-090-4`, `4-090-5`) and all seven LIR codes. All nine SUP
  codes in the two `changes/1109-*-SUP-*` patches are absent. Amendment rows
  add the country field to the seed's point/operator representation.

The previous reflected-SUP heuristic hid most seed-issue conflicts from the
skip ledger but still put those changes in history. It did not stop ADD/LIR
replay. The five real-corpus regression examples fail before the fix (5/5),
with histories containing the seed plus its own patches. After the fix they
assert seed-only history, no errors and complete preservation of seed entries.
Unflagged source tests still apply same-issue patches and retain later issues;
pre-seed evidence remains available to the existing reflected-SUP heuristic.

== Reproduce

Run from the repository root with the gem bundle and Ruby 3.4:

[source,sh]
----
git show dee5447dd69f958241f5a916e68d79439a2aef31:scripts/register_state_integrity_allowlist.jsonl > /tmp/g7-allowlist.jsonl
BUNDLE_GEMFILE=ituob/Gemfile bundle exec ruby -r liquid scripts/audit_seed_issue_replay.rb /tmp/g7-allowlist.jsonl
BUNDLE_GEMFILE=ituob/Gemfile bundle exec ruby -r liquid scripts/replay_skip_inventory.rb
BUNDLE_GEMFILE=ituob/Gemfile bundle exec rspec --options /dev/null -I ituob/lib -I ituob/spec -r liquid -r ituob ituob/spec/ituob/registers/directory_change_source_spec.rb ituob/spec/ituob/registers/seed_issue_replay_spec.rb
BUNDLE_GEMFILE=ituob/Gemfile bundle exec ruby -r liquid scripts/verify_parser_equivalence.rb --verify
----

The audit prints all 21 seeded registers and exits nonzero if any seed-issue
patch or G7 duplicate-add finding still reaches replay. The skip inventory drops
from 5 to 4: seed-issue errors go from 1 to 0, while the three source gaps and
one mis-filed patch remain. Parser baselines and amendment data are unchanged.
