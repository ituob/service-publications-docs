== Method

[source,sh]
----
metanorma -t itu -x pdf T-SP-F.32-2011-E.adoc        # in documents/T-SP-F.32-2011
ruby scripts/compare_official_pdf.rb GENERATED.pdf OFFICIAL.pdf \
  --data datasets/980-F.32/data.yaml \
  --dispositions docs/pdf/comparison-pilot-dispositions.yaml --out OUTDIR
----

Both PDFs go through `pdftotext -layout`; whitespace, curly quotes and case are
normalised. Two layers are diffed with a longest-common-subsequence diff:

rows:: Every layout line ending in a 4-character office code is a table row.
Rows align on the code *and* the name, so a dropped row inside a run of repeated
codes (26 `INNX` rows) is the row reported, not the last one. Rows that do not
align are paired by code alone. A name wraps differently in the two PDFs, so
each row also carries the text on the lines above and below it in its name
column; two names are the same text only when the lines, joined, read exactly
the same on both sides. A name that gained or lost a word is a *bug*, not a
wrap. A row only the generated PDF has is a *bug* unless the official text
carries it without it being a row there.
prose:: The preface words from "Note from TSB" up to the first table header,
list markers removed.

`--data` lets the script settle a missing row by measurement: a row absent from
the generated PDF is *data* if the dataset has no such record and a *bug* if it
does; a dataset record that never reaches the generated PDF is a *bug*. Codes
are not unique (the `--XX` codes are reused), so such a row counts as "in the
dataset" only when the code and a name match, and a row whose code and name
occur more than once is left for hand review.

`--dispositions` is the checked-in file `docs/pdf/comparison-pilot-dispositions.yaml`:
the human dispositions, each with a reason, matched on the exact delta text. An
entry that does not match exactly its `count` of open deltas is an error. The
script exits non-zero while any bug, unreviewed delta or bad entry remains, so
a passing run (`RESULT: PASS`) means every delta has a disposition and none is a bug.

== Findings that matter

. *The F.32 dataset is incomplete, not the generator.* All 823 data deltas are
rows the dataset lacks (Italy onward, plus Belarus). Fixing it is a data
task; no PDF fix will close it. Until then a generated F.32 PDF is 33 pages
against the official 47.
. *Fidelity of what is there is good.* Row order and office codes match
for all 676 rows, and names for all of them once the 6 dispositioned layout cases are read by eye; prose matches word for word apart from markers and spacing.
. *Out of scope here (C13).* The comparison is text and table content only. It
does not see layout fidelity (cover, header/footer, fonts), and the generated
cover differs visibly ("ITUPublications", "2011 edition" versus the official
"Annex to ITU Operational Bulletin No. 980 - 15.V.2011").

== Limits of the tool

* `pdftotext -layout` row parsing, not a PDF table extractor: a wrapped name is
joined from the lines in its column (up to three above and three below, six
lines scanned), so a name whose continuation shares a line with another row
(`CA--`) or a network cell read as the name (the five `U..` rows) needs a
disposition. A changed word in a wrapped name is caught, because the joined
text must match exactly.
* English only; the country column is trilingual and is not compared.
* The tool reports disposition `unreviewed` for anything its rules cannot
settle; this run had 4 (and 6 name differences it called bug), all dispositioned
in the checked-in file, each with a reason.
* Scaling to other publications needs their official PDFs (blocked on C9) and
a row definition per table shape.
